# 肉の価格表示 追加設計

- 作成日：2026-10-02
- 状態：著者承認済み（2026-10-02）
- 対象：マニラの野菜・魚介価格ページ

## 1. 目的と既存設計との関係

読者が、マニラ首都圏の主要な肉5品目について、現在の小売価格と2020年11月からの推移を既存のグラフで見られるようにします。毎週の自動更新にも同じ品目を含めます。

本書は[既存設計](2026-10-01-manila-market-prices-design.md)の追加設計です。既存設計2節の「肉を表示しない」という記述を、この5品目に限って変更します。既存設計12節を含むその他の決定は引き継ぎます。WordPress側は変更しません。

## 2. 表示する品目

| ID | 表示名 | PDFの主な名称 | 区分 |
| --- | --- | --- | --- |
| `whole_chicken` | 鶏肉（丸鶏） | Whole Chicken | 肉 |
| `pork_kasim` | 豚肉（カシム） | Pork Ham / Pork Kasim | 肉 |
| `pork_liempo` | 豚肉（リエンポ） | Pork Belly / Pork Liempo | 肉 |
| `beef_rump` | 牛肉（ランプ） | Beef Rump | 肉 |
| `beef_brisket` | 牛肉（ブリスケット） | Beef Brisket | 肉 |

5品目はすべて1 kg当たりの価格です。カシムとリエンポは部位名を表示名に残し、豚肉全体の価格と誤解されないようにします。日本語名・現地名・英語名は既存の `commodities.csv` の列を使います。

PDFの名称が無修飾、または `Local` と明示される場合を対象にします。`Imported`、`Frozen`、`fresh or chilled` など販売条件が別に示された行は、この5品目に合流させません。無修飾の名称から産地や保存状態を推定しません。表記ゆれの対応表は `data/unmapped.csv` に実在する名称を確認して登録します。同じ日に一つの品目へ複数行が対応する名称は、価格が混ざらないよう個別に点検します。

## 3. データの流れ

既存の収集・集計・表示の流れを使います。`data/commodities.csv` に `category=meat` の5行と名称の対応を追加します。PDFの読み取り結果は `NameMap` を通して `data/daily.csv` と `data/market_daily.csv` に入り、既存の `aggregate` が `data/weekly.csv` を作ります。`build_site` の分類に「肉」を追加し、`site/data.json` に5品目の週次系列を出します。画面の分類タブと品目選択はデータから自動生成されるため、グラフの仕組みは変えません。

首都圏系列には既存の優先順位（実勢価格、平均、値幅の中間）を使います。PDFにカルティマール市場の対象品目があれば市場系列にも入れます。著者の実測値には肉がないため、5品目の実測系列は空です。欠測時の線の切り方、0以下の価格の除外、前回価格の5倍を超える変動の除外を引き継ぎます。

2020年11月からの履歴は、台帳で解析成功となっている保存済みPDFをキャッシュから再解析して作ります。`data/unmapped.csv` は名前と出現回数だけで価格を持たないため、履歴の復元には使えません。再解析ではPDFをネットから取り直しません。キャッシュに無いPDFは取得せず、欠損として報告します。農業省の一覧ページへのアクセスは既存の収集手順に従います。テストから農業省へはアクセスしません。

## 4. 画面と説明文

分類タブの順序は「野菜／香味野菜／果物／魚介／肉」です。既存の `?item=<commodity_id>` を5品目でも使えるようにします。ページタイトル、README、埋め込み用のタイトルは肉を含む表現に改めます。価格の出典と単位は既存の表示に合わせ、実測値が無い品目では空の系列を描きません。

## 5. 点検と成功条件

名称の対応テストで、各品目の主要な時代別表記が正しいIDに対応し、輸入品・冷凍品・鶏卵が対応しないことを確かめます。JSON生成テストとブラウザテストで、肉タブ、5品目の表示、直接リンク、既存分類の維持を確かめます。読み取り部分に実物PDF由来の誤りが見つかった場合に限り、見本と期待値テストを先に追加して修正します。

再解析後は品目別に初日・最終日・週数・最大空白・除外件数を集計し、原PDFの代表例と照合します。特に2025年以降の品目名変更、過去との不自然な段差、カルティマール系列の有無を点検します。欠測や区別できない名称は推測で埋めず、点検結果に記録します。既存のPythonテストと画面テストが通り、公開データに5品目の有効な価格系列が入ることを成功条件とします。
